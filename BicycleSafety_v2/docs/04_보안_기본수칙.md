# BicycleSafety 기초 보안 수칙

1. **키 관리:** `local.properties`에는 각자 키를 저장하고 `.gitignore`로 제외. 카카오 네이티브 키는 플랫폼 설정(패키지명, 앱 서명 해시)으로 사용 범위를 제한. 카카오 REST 키는 APK에서 추출 가능하므로, **운영 배포시 팀 백엔드에서 대신 호출**하도록 변경 필요.
2. **HTTPS:** 팀 서버 URL은 HTTPS만 허용하도록 준비. 학교 내부 임시 HTTP 서버(`:8088`) 연동은 공개 인터넷 노출 없이 별도 협의 후 디버그 전용 구성.
3. **GPS 최소 권한:** 앱이 켜진 동안만 위치 권한 요청과 업데이트, 화면이 사라지면 일시 정지. 백그라운드 위치/항상 허용 권한 요구하지 않음. 정확도 나쁠 때 위험 경고 중지.
4. **위험 정확성:** 과거 사고다발지역 접근 시 **'과거 사고 이력'**이라고 안내. 실시간 사고·안전 보장·사고 회피를 주장하지 않음.
5. **계정:** 12/9 API가 오기 전에는 테스트 비밀번호를 하드코딩하거나 실제 계정을 임의로 만들어 로그인 성공 처리하지 않음. 로그인 구현시 전송은 HTTPS, 서버 측 해시, 입력 검증, 세션/토큰 만료 설계, 로그에 비밀번호 출력 금지.
6. **서버·DB:** 테스트 DB 계정과 비밀번호를 소스/스크린샷/공개 GitHub에 올리지 않음. 계정별 최소 권한; SQL PreparedStatement 사용. 데이터 수정·삭제 API는 인증 및 권한 검사 필수.
7. **공유:** 키가 노출된 적이 있다면 해당 서비스 콘솔에서 재발급/회전. 제출용 PDF에 키·토큰이 보이지 않게 캡처.
8. **Git:** 직접 main 덮어쓰지 말고 Jira 이슈별 브랜치와 PR로 협업. 예: `feat/s6-hazards-gps`, `feat/s7-route-result`.

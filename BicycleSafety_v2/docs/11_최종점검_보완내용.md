# 2026-11-24 마지막 독립 점검 — 보완 기록

## 실제로 발견한 동작 흐름 문제 및 수정

1. **경로 주변 마커 유지**: 기존에는 성공한 경로의 주변 사고 마커를 표시해도 GPS 좌표가 이전보다 900m 이상 움직이면 현재 위치 주변 마커로 전환되었습니다. 이제 경로가 열려 있는 동안은 `routeHazardsVisible` 목록을 보존하고, GPS가 갱신되어도 경로 주변 사고 마커를 유지합니다. 출발지/도착지 변경이나 새 경로 조회에서는 해당 목록을 초기화합니다.
2. **사고 데이터 비동기 도착**: 출발지·도착지 조회가 사고 JSON 로딩보다 먼저 끝나면 위험 건수가 '자료 준비 전'으로 남았습니다. 이제 사고 데이터 로딩이 끝나면 이미 있는 경로에 대해 주변 150m 위험 건수를 다시 계산해 지도와 경로 결과 메시지를 갱신합니다.
3. **경로 표시 실패 정리**: 지도에서 경로선을 그리지 못한 경우 결과 캐시를 정리해, 나중에 사고 자료가 도착하는 것만으로 실패한 경로가 성공 메시지로 바뀌지 않게 했습니다.

## 직접 확인한 범위

- Java 11 **가짜 Android/Kakao API 스텁을 이용한** 재컴파일 통과(실제 SDK 컴파일은 아님).
- `tests/check_sources.py`: XML 47개, JSON 2,079건, ID/좌표/키/중복소스 정적 검사 통과.
- `tests/check_route_flow.py`: 지도/GPS/사고 데이터/초기화 연결 흐름 정적 검사 통과.
- ZIP CRC 및 원본과의 파일 차이 재확인 예정.

## 여전히 학교에서 해야 하는 검증

- Android Studio Gradle Sync와 `assembleDebug` 성공 여부, 카카오맵 네이티브 초기화, 위치권한·실제 GPS 갱신, 경로 API, 지도 경로선, TTS 실기기 확인.
- 팀 서버 사고 API 및 회원 API는 미연결. 카카오 로그인은 12/9 작업 범위, 이 ZIP 미포함.
- `BIKE_ONLY`는 사고 회피 경로가 아니며 사고 이력은 150m 근접 참고 정보입니다.
- 마이페이지의 통계/기록은 UI 예시 값입니다.

이 기록은 **소스 검사 결과**이며 실제 동작이나 12/2 DoD의 팀장 승인·아카이브 업로드를 보장하지 않습니다.

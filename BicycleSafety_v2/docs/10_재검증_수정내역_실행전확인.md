## 이 ZIP에서 수정한 사항 (기존 Java/Kotlin 구조·UI v4·카카오 경로 API 그대로 유지)

1. **`gradle/gradle-daemon-jvm.properties` 제거**: 기존 ZIP의 `toolchainVersion=25`는 Android Studio 설정과 무관하게 JDK25를 요구해 수업 컴퓨터의 첫 Gradle 동기화를 방해할 수 있었습니다. 이제 Android Studio의 호환 Gradle JDK를 사용합니다. *참고: https://docs.gradle.org/current/userguide/gradle_daemon.html*
2. **`MainActivity.java` GPS 정확도 확인**: 위치 정보에 정확도 자체가 없을 때도 `150m` 근접 경고가 실행될 수 있던 조건을 수정했습니다. 정확도 확인 불가 또는 오차 80m 초과일 때 접근 판별을 보류합니다. 이 판단은 **오프라인 사고 중심좌표와의 거리 기반 시연**이며 실제 안전 판단이 아닙니다.
3. **`README.md`(구 `README_먼저읽기.md`) 보완**: 학교 PC의 JDK 강제 다운로드를 피하는 설정 가이드를 명시했습니다.

## 현재 실행 여부·남은 문제 (완료 처리 금지)

- **실제 Gradle Sync/assembleDebug 및 Pixel 에뮬레이터 실행은 이 환경에 Android SDK/의존성이 없고 네트워크가 제한되어 수행하지 못했습니다.**
- 카카오 REST 키, 네이티브 앱 키, 네트워크 권한, 학교 PC의 Android API 37, 카카오맵 네이티브 호환성 확인 필요
- 로그인/회원가입: **12/9 일정, 미구현**. GitHub 패치도 이 ZIP에 자동 합치지 않음
- 팀의 서버 사고 API/위험 판별 API: 실제 응답 계약·HTTPS 주소를 받지 못했으므로 **실서버 연동 완료가 아님**
- 위치 경고는 공공데이터의 중심좌표 기준 150m 근접 테스트, 안전 보장 아님
- 경로 안내는 첫 TTS 발화 및 55m 이내 다음 단계 테스트 수준이지 완전한 실도로 내비게이션 아님
- `MainScreen.kt` 마이페이지에 있는 주행 수치·기록은 UI **예시 데이터**이고 실제 기록 데이터가 아닙니다.

## 내일 학교에서 가장 먼저 확인할 순서

1. `README.md`의 `local.properties` 설정 후 **Gradle Sync → Make Project**
2. 실행해서 안전 확인 팝업 → 실제 지도 표시 → 오프라인 사고 마커 클릭
3. 서울역 → 상계역 실제 경로선·거리·시간 및 경로 주변 과거 사고 건수 확인
4. 현재 위치 권한 허용·거부 테스트 → 에뮬레이터 가상 위치로 경고·TTS 테스트
5. `docs/03_학교실습_체크리스트.md`에 결과를 기록하고 실패 시 **첫 번째 Build 오류 또는 Logcat `FATAL EXCEPTION`**을 복사
